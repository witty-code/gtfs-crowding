# ניתוח עומס רציפים מקובץ GTFS

כלי דפדפן סטטי לזיהוי תחנות ורציפים שבהם מתוכננות **יותר מדי יציאות אוטובוס בו-זמנית**.
כל העיבוד מתבצע מקומית בדפדפן — הקובץ לא נשלח לשום שרת, ואין צורך בשרת צד-אחורי.

---

## מה הכלי מודד

| דירוג | הגדרה | למה זה חשוב |
|---|---|---|
| **רמה א׳** | יציאות המתוכננות ל**אותה דקה בדיוק** מאותו רציף | תכנון בלתי אפשרי פיזית |
| **רמה ב׳ — מוצא** | יציאות בטווח **±4 דק׳** בתחנת מוצא | שעות המוצא מתוכננות ומחייבות |
| **רמה ב׳ — ביניים** | יציאות בטווח **±2 דק׳** בתחנת ביניים | שעות לאורך המסלול משוערות בלבד |

החלונות ניתנים לשינוי בממשק.

**תחנת מוצא** מזוהה כ-`stop_sequence` המינימלי של הנסיעה — גם אם הקובץ אינו ממוין.
זה הפוקוס העיקרי של הכלי: בתחנת מוצא שעת היציאה היא נתון מתוכנן ומחייב, ולכן חפיפה שם
היא ראיה ישירה לתכנון לקוי, בעוד שזמני ההגעה לאורך המסלול דינמיים ומשוערים.

### חישוב קיבולת לפי אורך התחנה

מזינים אורך תחנה במטרים, והמערכת מחשבת:

```
קיבולת   = ⌊ אורך התחנה ÷ אורך אוטובוס ⌋      (ברירת מחדל 12 מ׳)
אורך נדרש = מספר היציאות בשיא × אורך אוטובוס
```

תחנה מסומנת כחריגה רק כאשר מספר היציאות החופפות **עולה על הקיבולת**.
אפשר להגדיר אורך ברירת מחדל גלובלי, ולדרוס אותו לכל תחנה בנפרד ישירות בטבלה —
הדריסות נשמרות ב-`localStorage` של הדפדפן ונשארות בין ביקורים.

## שימוש

1. גוררים קובץ `GTFS.zip` (או מעלים קבצי `txt` בודדים). פיד עדכני:
   [gtfs.mot.gov.il/gtfsfiles](https://gtfs.mot.gov.il/gtfsfiles/)
2. לוחצים **סרוק את הפיד** — שלב מהיר שקורא הכול חוץ מהקובץ הכבד, ומגלה מה יש בפיד:
   טווח התאריכים, מספר הנסיעות לכל תאריך, ומבנה לוח השנה.
3. בוחרים תאריך מתוך רשימת התאריכים של הפיד עצמו, טווח שעות ושאר ההגדרות.
4. לוחצים **הרץ ניתוח**. אפשר **לעצור** בכל רגע.
5. לוחצים על שורה בטבלה כדי לראות את היציאות, **מקובצות לפי דקת יציאה**, עם `trip_id`
   ומק"ט לאימות מול מערכות אחרות.
6. לשונית **מפה** מציגה את התחנות החריגות גיאוגרפית, בצבע לפי חומרה ובגודל לפי מספר היציאות בשיא.
7. **ייצוא CSV** מפיק דוח מלא (עם BOM, נפתח נכון בעברית באקסל).

### הגדרות מרכזיות

**היקף עצירות**
- `תחנות מוצא בלבד` — מהיר וחסכוני בזיכרון. שומר שורה אחת לכל נסיעה, ולכן שינוי יום או
  טווח שעות מתעדכן מיידית ללא קריאה חוזרת של הקובץ. **מומלץ להתחלה.**
- `כולל תחנות ביניים` — קורא את כל `stop_times.txt`. איטי וכבד בזיכרון בפידים ארציים.
  שינוי יום או הרחבת טווח שעות מחייבים קריאה חוזרת (הכלי עושה זאת אוטומטית).

**יחידת ניתוח**
- `רציף בודד (stop_id)` — כל שורה ב-`stops.txt` היא נקודת עצירה נפרדת.
- `תחנת אם (parent_station)` — מאחד רציפים תחת התחנה שלהם. בפידים שבהם `parent_station`
  ריק (כמו ברוב הפיד הישראלי), שתי האפשרויות זהות והכלי מציג על כך התראה.

**תאריך מול יום בשבוע — חשוב** — ברירת המחדל היא **תאריך מסוים**, וזו גם הבחירה הנכונה
כמעט תמיד. שתי סיבות:

1. **פידים שמבוססים על `calendar_dates` בלבד** (כמו `Gtfs_10_days.zip` של משרד התחבורה)
   לא מסמנים ימי שבוע ב-`calendar.txt` כלל. סינון "יום בשבוע" יחזיר עליהם **אפס תוצאות**.
   הכלי מזהה זאת בסריקה ומתריע.
2. **פיד שמכיל כמה גרסאות לוח זמנים** מגדיר לעיתים שני `service_id` שונים עם אותו דגל
   יום־בשבוע, בטווחי תאריכים סמוכים. סינון לפי יום בשבוע יפעיל את שתיהן ו**יספור כל נסיעה
   פעמיים**. הכלי משווה את מספר השירותים הפעילים ביום־בשבוע מול תאריך בודד, ומתריע כשיש
   פער שמעיד על ספירת יתר.

בחירת תאריך מתחשבת ב-`calendar_dates` (חגים ושינויים חד-פעמיים) ובטווח `start_date`/`end_date`,
ולכן היא גם מה שמאפשר השוואה מול הביצוע בפועל באותו יום.

**שעות מעל 24:00** — נשמרות כמות שהן לפי מוסכמת GTFS (נסיעה ב-25:10 שייכת ליום השירות
הקודם) וניתנות לבחירה בטווח השעות כ-"24:00 (למחרת)" והלאה.

## לוחות זמנים וייצוא ל-Canva

לשונית **לוחות זמנים** מציגה לכל קו את שעות היציאה שלו מתחנת המוצא באותו יום,
לפי כיוון, כששעה שיוצאים בה יותר מאוטובוס אחד מסומנת ב-`×N`.

**ייצוא ל-Canva** מפיק CSV בפורמט Bulk Create — שורה אחת לכל קו:

| עמודה | תוכן |
|---|---|
| `Line_Number` | מספר הקו |
| `Destination` | שם המסלול |
| `Direction_1_Name` / `Direction_2_Name` | שמות המוצא בכל כיוון |
| `Agency`, `Makat`, `Service_Date` | מפעיל, מק״ט ותאריך השירות |
| `Dir1_Times` / `Dir2_Times` | כל השעות בתא אחד, מופרדות ברווח |
| `Dir1_Time_1` … `Dir1_Time_N` | כל שעה בעמודה נפרדת, למי שמעצב גריד |

שעה שיוצאים בה כמה אוטובוסים מסומנת ב-`*X` (למשל `10:47*2`), בשתי צורות הייצוא.

## מדידת אורך תחנה

בחלון הפירוט יש כפתור **מדוד אורך תחנה**: נפתחת מפה בתקריב על התחנה, לוחצים על
קצותיה, והכלי מחשב את המרחק במטרים ואת מספר האוטובוסים שנכנסים בו. **שמור כאורך
התחנה** מעדכן את הקיבולת ואת הדירוג, ונשמר בדפדפן גם להרצות הבאות.

## הערות טכניות

- פריסת ה-ZIP נעשית עם `DecompressionStream('deflate-raw')` המובנה בדפדפן — ללא ספריות
  חיצוניות וללא CDN. תומך גם ב-ZIP64.
- כל הקריאה היא בזרימה (streaming), כך ש-`stop_times.txt` בגודל של מעל 1GB אינו נטען
  לזיכרון בבת אחת.
- העיבוד רץ ב-Web Worker, כך שהממשק נשאר רספונסיבי ומציג התקדמות.
- דרישות דפדפן: Chrome/Edge 103+, Firefox 113+, Safari 16.4+. בדפדפן ישן יותר אפשר
  להעלות קבצי `txt` בודדים.
- **פענוח CSV סלחני:** בפיד הישראלי יש שמות תחנה עם גרשיים בשדות שאינם מצוטטים
  (למשל `ת.רק"ל הקוממיות/דרך בגין`). מנתח CSV תמים בולע בגללן את שאר השורה לתוך שם
  התחנה ומאבד את הקואורדינטות. הכלי מתייחס למרכאה כפותחת שדה רק אם היא התו הראשון
  בשדה, ומאחה אוטומטית שורות שבהן שדה טקסט הכיל פסיק בלי ציטוט.
- **חייב לרוץ דרך שרת ולא כקובץ מקומי.** דפדפנים חוסמים Web Worker מ-`file://`, והכלי
  מזהה זאת ומציג הסבר עם פתרון.
- Leaflet ואייקוני Lucide מוטמעים בתיקיית `vendor/` ולא נמשכים מ-CDN, כדי לעבוד גם מאחורי
  סינון רשת. אריחי המפה עצמם כן נמשכים מ-`tile.openstreetmap.org`; אם הם חסומים, שאר הכלי
  ימשיך לעבוד והמפה תישאר ריקה.
- **פיד ארצי מלא**: במצב "כולל תחנות ביניים" מומלץ להתחיל מטווח שעות מצומצם (למשל 06:00–09:59).
  יש תקרת בטיחות של 6 מיליון עצירות שמורות, ומעליה מוצגת התראה.

## מבנה הקוד

| קובץ | תפקיד |
|---|---|
| `index.html` | הממשק והעיצוב (RTL, מצב בהיר וכהה) |

| `test/ui-test.mjs` | 72 בדיקות ממשק מקצה לקצה בדפדפן אמיתי |
| `test/make-sample.mjs` | מחולל פיד לדוגמה; `node test/make-sample.mjs big` מייצר פיד גדול |
| `test/subpath-test.mjs` | מוודא שהאתר עובד תחת נתיב משנה של GitHub Pages |

### הרצת הבדיקות

```bash
npm install                     # playwright, לבדיקות הממשק בלבד
node test/make-sample.mjs       # מייצר test/sample-gtfs.zip
node test/make-sample.mjs big   # מייצר פיד גדול לבדיקות עצירה והערכת זמן
node test/run-test.mjs          # בדיקות ליבה
node test/ui-test.mjs           # בדיקות ממשק
```

## פריסה ב-GitHub Pages

האתר סטטי לחלוטין וכל הנתיבים יחסיים, כך שהוא עובד גם תחת `username.github.io/repo/`.

```bash
git init
git add .
git commit -m "כלי ניתוח עומס רציפים מ-GTFS"
git branch -M main
git remote add origin https://github.com/<user>/<repo>.git
git push -u origin main
```

ואז ב-GitHub: **Settings → Pages → Source: Deploy from a branch → main / (root)**.

הקובץ `.nojekyll` כלול כדי ש-Jekyll לא יתעלם מקבצים. כל דחיפה ל-`main` מתפרסמת
אוטומטית תוך כדקה — אין צורך ב-GitHub Actions.

> **הערה על אבטחה:** האתר אינו מוגדר עם `Cross-Origin-Isolation`, ואינו זקוק לכך.
> אין שום תעבורת רשת מלבד טעינת שלושת קבצי ה-JS.
